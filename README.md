# Окна CRM — демо на HeroUI Pro

Демо интерфейса CRM для компании, которая продаёт и устанавливает окна. Собрано на готовых компонентах [HeroUI](https://heroui.com) v3 и [HeroUI Pro](https://heroui.pro) по их документации: каркас `AppLayout`, `Sidebar`, `Navbar`, `DataGrid`, `ListView`, `Segment`, `EmptyState`, а также `Autocomplete`, `Select`, `Modal`, `Tabs`, `Alert`, `Pagination`, `Toast` и другие.

Данные выдуманные и хранятся только в памяти браузера: после перезагрузки страницы всё возвращается к исходному виду.

## Что можно посмотреть

**Заявки** (`#/leads`)
- Список с поиском и фильтрами «Ждут ответа» и «Без источника».
- Карточка заявки (`#/leads/441`):
  - стадия заявки;
  - клиент и объект;
  - выбор ответственного с поиском и группами по должностям;
  - канал обращения;
  - источник трафика: если нужного источника нет, менеджер вписывает его сам, и он сразу попадает в справочник;
  - сумма;
  - позиции заказа с количеством и итогом по прайсу;
  - заметка;
  - блок «Ждёт ответа» (пропущенный звонок, непрочитанные сообщения);
  - задачи.

**Звонки** (`#/calls`)
- Журнал звонков на Pro `DataGrid`: сортировка, закреплённая колонка даты, меняемая ширина колонки «Владелец», выбор видимых колонок, поиск по номеру или имени, фильтр по итогу, постраничный вывод на 25 или 50 строк.

**Настройки → справочники** (`#/settings/channels` и другие)
- Порядок значений меняется перетаскиванием за ручку слева. Мышью, пальцем и с клавиатуры.
- Звёздочка — значение по умолчанию. Глаз — скрыть значение из новых форм.
- Значение, которое уже где-то выбрано, удалить нельзя: подсказка предложит его скрыть.
- Справа живой предпросмотр: так поле выглядит в форме с несохранёнными настройками.
- Внизу панель «Сохранить» с сочетанием ⌘S / Ctrl+S.

**Настройки → UTM-метки** (`#/settings/utm`)
- Правила «поле — условие — значение — источник трафика». Порядок важен, его тоже меняют перетаскиванием.
- Подсказка, у скольких заявок без источника можно проставить его по правилам, и кнопка «Проставить источник».
- Вкладка «Пришедшие метки»: метки, под которые нет правила, и создание правила из них в один клик.
- Вкладка «Ссылка с UTM»: сборка рекламной ссылки.

**Оформление** (кнопка с палитрой в шапке)
- Готовые темы HeroUI Pro: «Стандарт», Glass, Mouve, Brutalism. У каждой есть светлый и тёмный режим.
- Выбор запоминается в браузере.

Вёрстка адаптирована под телефон.

## Запуск

Нужен доступ к HeroUI Pro (`npx heroui-pro login`).

```bash
bun install --ignore-scripts      # зависимости без install-скриптов
./node_modules/.bin/heroui-pro install   # скачать код Pro-компонентов по лицензии
bun run dev
```

Сборка статики в `dist/`: `bun run build`. Пути в сборке относительные, поэтому её можно открыть из любой папки, в том числе на GitHub Pages.

## Устройство кода

Код разложен по слоям [Feature-Sliced Design](https://feature-sliced.design). Каждый слой импортирует только слои ниже себя.

| Слой | Что внутри |
| --- | --- |
| `app` | Корень приложения: разбор адреса, локаль `ru-RU`, уведомления |
| `pages` | `leads` — заявки, `calls` — звонки, `settings` — настройки |
| `widgets` | `app-shell` — каркас на AppLayout, `directory-editor` — редактор справочника, `utm-rules` — UTM-правила, `lead-card` — карточка заявки, `calls-table` — журнал звонков |
| `features` | `save-changes` — панель сохранения с ⌘S, `create-directory-item` — выбор значения с добавлением нового |
| `entities` | `directory` — справочники, `lead` — заявки и продукция, `employee` — сотрудники и выбор сотрудника, `call` — звонки, `utm-rule` — правила UTM-меток |
| `shared` | Маленькое хранилище, hash-роутер, темы, защита несохранённых правок, форматирование, склонения, кнопка-иконка с подсказкой |

Решения, которые стоит знать:
- **Хранилище.** Своё, на `useSyncExternalStore`, примерно на 20 строк. Формы правят черновик, а в хранилище он попадает только по кнопке «Сохранить».
- **Роутинг на hash.** Так адреса работают на GitHub Pages без настройки сервера.
- **Несохранённые правки.** Пока в форме есть несохранённые правки, уйти со страницы нельзя: ни через меню, ни кнопкой «Назад», ни закрытием вкладки. Появится подсказка сохранить или отменить их.
- **Темы.** Компонентные стили тем HeroUI Pro не привязаны к `data-theme`, поэтому CSS выбранной темы подгружается по требованию, а прежний удаляется (`shared/lib/theme.ts`). Тема включается атрибутом `data-theme` на `<html>`, как описано в документации. Glass делает стеклянными карточки, поля и попапы. Чтобы стеклянной стала и боковая панель, `AppLayout` в этой теме получает `sidebarVariant="floating"`. Стеклу нужен насыщенный фон: на витрине heroui.pro под Glass лежит размытая фотография. Штатный `--background-gradient` очень бледный, поэтому в демо под стеклом свой mesh-градиент с тёплым и холодным светом, а шапка получает то же размытие `--glass-blur` (`app/styles.css`). В тёмном режиме Glass панели почти прозрачные, в светлом — матовые. Так задумано самой темой.
- **Списки с перетаскиванием.** Это Pro `ListView` с `dragAndDropHooks` из `react-aria-components`: `ListView` построен на RAC `GridList`.
- **Поля ввода внутри строк `ListView`.** Обёрнуты в `KeyboardIsolation`, иначе строка перехватывает пробел и буквы для своей навигации.
- **Сортировка звонков.** Она управляемая (`sortDescriptor`) и применяется ко всему отфильтрованному списку до разбивки на страницы. Иначе `DataGrid` сортировал бы только текущую страницу.
- **Проп `dependencies`.** Его получают коллекции, которые рисуют строки из внешних данных, например значение по умолчанию. Без него RAC не перерисует строку.

## Про установку HeroUI Pro

- Зависимости ставятся с `--ignore-scripts`, а код Pro-компонентов скачивает команда `heroui-pro install`.
- `tailwind-variants` закреплён на ветке 3.x: с 4.x Pro-компоненты падают с ошибкой `twMergeConfig`.
- `bun audit` находит одну уязвимость: `figlet` в CLI `heroui-pro` (риск зависания при рисовании ASCII-баннера в терминале). В сборку приложения `figlet` не попадает.
